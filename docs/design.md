# 指尖跳跳 (Jump Orbits) - 游戏设计文档

## 1. 游戏概述

### 1.1 游戏简介
指尖跳跳（Jump Orbits）是一款基于反应速度和节奏感的2D休闲小游戏，适合在微信小游戏、抖音小游戏等平台上发布。玩家通过点击屏幕控制自己的星球从外层轨道向内层轨道跳跃，避开轨道上运行的其他星球，尽可能深入到更多的内层轨道以获取更高分数。

### 1.2 核心玩法
- 多层圆形同心轨道，每层轨道上有不同数量的星球
- 玩家从最外层轨道开始，点击屏幕向内层跳跃一次
- 成功避开内层轨道上的星球就得分，碰撞则游戏结束
- 轨道无限层，玩家目标是获得最高分数
- 最外层三层轨道作为安全区域，不生成障碍星球，便于玩家熟悉游戏

### 1.3 目标用户
- 休闲游戏爱好者
- 小游戏平台用户（微信、抖音等）
- 适合各个年龄段玩家，尤其是碎片时间娱乐需求的用户
- 不需要高游戏技巧的普通大众玩家

## 2. 游戏机制详解

### 2.1 轨道系统
- **轨道布局**：同心圆轨道设计，从外到内半径逐渐减小,最内层圆轨半径和轨道间距一样大
- **轨道数量**：理论上无限层，初始显示5层
- **轨道编号**：
  - 从外向内编号，最外圈为第1圈，依次向内递增
  - 轨道数组中的索引（index）与圈数关系：圈数 = 总轨道数 - index
  - 例如5层轨道时：最外圈index=4（第1圈），最内圈index=0（第5圈）
- **安全区域**：最外层三层轨道不生成障碍星球，作为玩家的安全起始区域
- **轨道特性**：
  - 轨道使用Canvas 2D绘制圆形轨道，外层轨道线条更粗，内层轨道线条更细
  - 轨道透明度也有区分，外层轨道透明度低（更明显），内层轨道透明度高（更淡）
  - 轨道使用简单的颜色区分，不需要复杂纹理
  - 玩家每进入一层，所有轨道半径增加一个轨道间距大小，同时圆心位置出现一个新的圆轨，半径和轨道间距一样大

#### 特殊轨道设计
- **生成规则**：
  - 前几圈为安全区（由配置项SAFE_TRACK_COUNT决定，默认为3圈），从安全区后的第一个圈（默认为第4圈）开始计算
  - 特殊轨道间隔由配置项SPECIAL_TRACK_INTERVAL决定，默认为10圈
  - 第一个特殊轨道的位置 = 安全区轨道数量 + 1 + 特殊轨道间隔
  - 默认情况下：第一个特殊轨道位于第14圈（3 + 1 + 10）
  - 后续特殊轨道的位置计算方式：前一个特殊轨道位置 + 1 + 特殊轨道间隔
  - 默认情况下：第二个特殊轨道位于第25圈（14 + 1 + 10），第三个特殊轨道位于第36圈（25 + 1 + 10）
  - 这确保了每两个相邻特殊轨道之间正好有10个普通轨道
  - ThemeManager和TrackSystem使用相同的判断逻辑确保特殊轨道识别的一致性
  - 特殊轨道使用金色（色相45度）显示，并带有发光效果
- **视觉效果**：
  - 使用金色（HSL: 45, 80%, 65%）
  - 添加发光效果（shadowBlur=15）
  - 透明度设置为0.8
- **功能效果**：
  - 清除当前轨道到最外层的所有障碍物
  - 触发粒子爆炸效果
  - 返回清除的障碍物数量用于计算额外得分

### 2.2 游戏架构设计
- **Canvas管理**：
  - Canvas元素由外部（main.js）创建和管理
  - 游戏实例（WebGame）通过构造函数接收canvas参数
  - 这种设计便于跨平台移植（如微信小游戏）
  - 平台适配层负责提供符合Web标准的canvas接口

### 2.3 星球设计
- **玩家星球**：
  - 开始位于最外层轨道
  - 使用简单的几何形状和颜色区分于其他星球
  - 跳跃时有简单的动画效果
- **障碍星球**：
  - 从外向内第4圈开始，每圈随机生成0-8个障碍星球
  - 同一轨道上的障碍星球完全均匀分布，形成对称图案
  - 初始位置随机，沿轨道匀速运动
  - 当玩家跳跃创建新轨道时，原有障碍星球保持在原轨道上
  - 新创建的轨道如果是第4圈及以内，也会随机生成障碍星球
  - 使用简单几何形状，颜色区分不同类型
  - 注重视觉清晰度，确保玩家能够轻松识别

#### 障碍星球消失效果
- **粒子系统设计**：
  - 使用对象池模式（默认200个粒子）
  - 每个障碍球消失产生12个粒子
  - 粒子继承障碍球的颜色
  - 360度扩散效果
- **粒子参数**：
  - 基础速度：3（随机增加0-2）
  - 生命周期：30-40帧
  - 粒子大小：2-3像素
  - 带有轻微重力效果（每帧Y速度+0.1）
- **性能优化**：
  - 使用对象池避免GC压力
  - 只更新和渲染活跃粒子
  - 使用简单的圆形几何体
  - 透明度随生命周期渐变

### 2.4 操作机制
- **简单点击**：玩家只需点击屏幕，星球自动跳向内层轨道
- **滑动操作**：
  - 向球移动方向滑动：增加跳跃惯性，使球在新轨道上位置更靠前
  - 与球移动方向相反滑动：减少跳跃惯性，使球在新轨道上位置更靠后
  - 滑动强度影响惯性大小，且有视觉反馈指示器
- **自动前进**：一旦成功跳入内层轨道，玩家星球自动在该轨道上运行
- **无多余操作**：保持操作简洁，确保易于上手

### 2.5 跳跃机制
- **跳跃距离**：每次跳跃固定前进一层轨道
- **跳跃轨迹**：从当前位置直线穿过到内层对应位置
- **跳跃时间**：跳跃动画约0.2-0.3秒，保持流畅感
- **跳跃冷却**：极短的跳跃冷却时间（0.1秒），防止误触但不影响游戏节奏
- **跳跃事件系统**：
  - `onPlayerStartJump`：玩家开始跳跃时触发，创建新的轨道和更新现有轨道动画
  - `onPlayerLand`：玩家落地时触发，检查是否落在特殊轨道上并触发相应效果
  - 两个事件共同构成完整的跳跃循环，确保游戏机制正常运行

### 2.6 碰撞检测
- **碰撞判定**：
  - 玩家星球与轨道星球的简单圆形碰撞判定
  - 设置适当的碰撞宽容度，提升休闲游戏体验
- **碰撞结果**：
  - 碰撞后游戏结束
  - 显示简单的消散特效
  - 展示最终得分和最高记录

## 3. 难度设计（休闲友好型）

### 3.1 难度递进曲线
- **安全区域**（前3圈）：
  - 无障碍星球，让玩家熟悉基本操作
  - 轨道宽度较大，便于玩家上手

- **速度区间设计**：
  - 基础速度：1.0弧度/秒
  - 每个区间长度：10个轨道
  - 区间间隔：1个轨道
  - 每个区间速度增量：0.1弧度/秒
  - 最大速度上限：2.5弧度/秒
  - 速度增长公式：当前速度 = 基础速度 + (区间序号 + 1) * 速度增量
  - 达到最大速度的区间：第8个区间（约80圈）

- **障碍物数量设计**：
  - 基础障碍物总数：20个
  - 每个区间增量：5个
  - 最大总数上限：50个
  - 每个轨道最少2个最多8个障碍物
  - 数量增长公式：当前区间总数 = min(基础总数 + (区间序号 * 增量), 最大总数)
  - 达到最大数量的区间：第6个区间（约60圈）
  - 具体区间划分：
    - 区间1 (4-13圈)：总共20个障碍物
    - 区间2 (15-24圈)：总共25个障碍物
    - 区间3 (26-35圈)：总共30个障碍物
    - 区间4 (37-46圈)：总共35个障碍物
    - 区间5 (48-57圈)：总共40个障碍物
    - 区间6 (59-68圈)：总共45个障碍物
    - 区间7 (70-79圈)及以后：总共50个障碍物（达到上限）
  - 障碍物在区间内均匀分配到各轨道，确保每个轨道不少于最小值且不超过最大值

### 3.2 难度调节因素
- **障碍星球数量**：
  - 区分两种场景的障碍球生成规则：
    - 特殊轨道之间：总障碍球数量固定可配（默认40个）
    - 特殊轨道之间的普通轨道：每个轨道分配2-8个障碍球，由总数均匀分配
    - 非特殊轨道区域：总障碍球数量固定可配（默认20个），每个轨道随机生成2-8个障碍球
  - 特殊轨道间的轨道数量固定为SPECIAL_TRACK_INTERVAL个普通轨道（默认10个）
  - 非特殊轨道区域的定义：从安全区后的第一个圈（默认为第4圈）到第一个特殊轨道（默认为第14圈）之前的区域
- **星球移动速度**：随层数增加而加快，但确保反应时间充足
- **轨道星球排列**：同一轨道上均匀分布
- **避免挫折体验**：通过平衡特殊轨道之间的障碍球总数，确保游戏难度的一致性

## 4. 评分系统与奖励

### 4.1 基础得分规则
- 每成功跳入一层普通轨道：+1分
- 跳入特殊轨道：不得基础分，但会清除外层所有障碍球，每清除一个障碍球得2分

### 4.2 额外得分机制
- **简单收集物**：轨道上可能出现简单形状的收集物，增加得分
- **特殊星球**：触碰某些特殊标记的星球可获得额外分数而非失败
- **每日挑战**：完成简单的每日任务获得额外奖励

### 4.3 排行榜系统
- **好友排行**：与小游戏平台好友比较最高分
- **全球排行**：所有玩家的最高分排名
- **每周/每日挑战**：定期刷新的特殊排行榜

#### 目录结构说明
- `/platforms/web/js/libs`：平台无关的基础类库，可被所有平台复用
  - `/core`：核心游戏类的基类实现
  - `/objects`：游戏对象的基类实现
  - `/utils`：通用工具和基础配置

- `/platforms/web/js/core`：Web平台特定的游戏核心实现
  - 继承和扩展libs中的基类
  - 实现Web平台特定的功能
  - 包含各种主题特效系统

- `/platforms/web/js/ui`：Web平台的UI组件实现
  - 所有游戏界面和交互组件
  - 使用Web技术（HTML/CSS/JS）实现

- `/platforms/web/js/utils`：Web平台特定的工具和配置
  - 包含Web平台的特定配置（GAME_CONFIG）
  - 继承和扩展基础配置（BASE_CONFIG）

#### 跨平台移植说明
1. 新平台开发时，直接复用`/js/libs`目录
2. 在新平台目录下创建对应的目录结构
3. 实现平台特定的适配器和UI组件
4. 确保配置系统正确继承基础配置

#### 配置分离设计
- **基础配置 (BASE_CONFIG)**：
  - 位于`/js/libs/utils/config.js`
  - 包含所有平台通用的游戏参数
  - 被所有平台的配置继承

- **平台配置 (GAME_CONFIG)**：
  - 位于各平台的`/js/utils/config.js`
  - 继承并扩展BASE_CONFIG
  - 添加平台特定的配置参数
